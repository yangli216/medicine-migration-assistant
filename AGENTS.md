# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Product direction

- The selected concept is the third generated direction: a guided migration assistant for non-expert integrators.
- Preserve the plain-language, one-decision-per-screen flow, mint/teal healthcare visual system, smart field recommendations, immediate sample preview, and optional expert-mode escape hatch.
- The core prototype path is: select a suggested legacy field, inspect or resolve the data-quality warning, confirm the mapping, and continue to the next required field.
- The production target is a lightweight Tauri desktop application, not a Java service or browser-only deployment.
- Rust owns source/target database access, row-level transactions, retry orchestration, local SQLite batch history, and audit records.
- Write target audit timestamps through database-typed expressions or typed driver parameters; never bind formatted timestamp text and rely on session-specific implicit conversion. Row failures must preserve the target table, write stage, and recognizable vendor error code so failed batches are safe to diagnose and retry.
- Treat `Asia/Shanghai` (`+08:00`) as the PHIS business time zone for target writes. Explicitly configure Oracle and PostgreSQL-wire-compatible target sessions before using `CURRENT_TIMESTAMP`, because PHIS stores business time in timestamp columns without a time-zone component and its inventory-flow date filters bind local timestamps; never inherit a UTC driver/session default that shifts migrated records by eight hours. Write first-stocktake business timestamps at millisecond precision, matching PHIS Java `Timestamp` values, instead of retaining a database server's default microsecond precision.
- Present Oracle failures with the extracted ORA code, a clear Chinese cause, and an actionable suggestion. Suppress undecodable driver text containing replacement characters from user-facing messages while retaining recognizable SQLState/native codes for diagnosis.
- Keep transient success notifications brief, but leave error notifications visible for at least 15 seconds and provide an explicit close action. Clear any previous notification timer before showing a new message so an older timeout can never dismiss a newer database error.
- Every primary key written to the target database must be a lowercase 24-character MongoDB ObjectId-compatible hex string, matching `new ObjectId().toString()`.
- Treat `hi_bd_med_alias` as the standard nine-column tenant-level alias table (`id_med_alias,id_med,na_alias,fg_main,py,wb,instr,id_tet,fg_active`). Never require or write `fg_pri` or `id_org` on this table; private ownership remains on the medicine/product records. For 二系列phis, carry readable `YK_TYPK.PYDM/WBDM` values into the main alias when available and build `instr` as name, pinyin, and Wubi without exceeding target lengths.
- Database profiles must support MySQL, Oracle, Dameng/DM8, openGauss/GaussDB, Vastbase, GBase 8c/8a/8s, and KingbaseES/PostgreSQL-family systems. Prefer the bundled PostgreSQL wire protocol for PostgreSQL-compatible branches (PostgreSQL, openGauss/GaussDB, Vastbase, GBase 8c and compatible KingbaseES); never route GBase 8a/8s through it. Prepare and validate database delivery for Windows x64 first, macOS second. Bundle license-compatible protocol implementations, but for vendor drivers that cannot be redistributed, show exact platform-specific installation steps and official download/support URLs in the connection UI. Keep vendor-specific connection details behind the guided connection form instead of exposing dialect complexity to integrators.
- Tolerate PostgreSQL-wire-compatible servers that incorrectly localize the protocol's nonlocalized severity field. Preserve SQLSTATE and the real database message even when `S` or `V` contains localized or unknown severity text, so schema and permission failures remain diagnosable instead of collapsing into an `unknown severity` protocol error.
- Bundle the unmodified Oracle Instant Client 19.31 full Basic and ODBC packages in Windows x64 installers. Fetch only from Oracle's official URLs during the Windows build, verify pinned SHA-256 values, retain both Oracle license files, register a uniquely named application-owned ODBC driver through elevated NSIS hooks, remove only that registration on uninstall, resolve saved `Oracle 19 ODBC driver` aliases to the application-owned driver, and verify both installed files and the 64-bit ODBC registry entry in release acceptance.
- Treat legacy Oracle 11g compatibility explicitly: the bundled 19.31 client supports Oracle Database 11.2.0.4 and later, while earlier 11g patch levels require a user-installed matching 64-bit Oracle ODBC driver or a server patch upgrade. Diagnose `ORA-01017` as a reached-service authentication failure (credentials, password case, service identity, or legacy password verifier), diagnose `ORA-28040` as an authentication-protocol mismatch, and never weaken `SQLNET.ALLOWED_LOGON_VERSION_CLIENT` automatically.
- Keep dynamically generated Oracle typed-NULL projections within Oracle 11g standard datatype limits. In particular, never declare `NVARCHAR2(4000)`; use the shortest compatible placeholder such as `CAST(NULL AS NVARCHAR2(1))` because Oracle 11g standard configuration limits `NVARCHAR2` to 2000 characters and otherwise raises `ORA-00910` before the read begins.
- Normalize each Oracle character operand before applying `NVL`, `COALESCE`, `CASE`, or `UNION`; an outer cast is too late to prevent `ORA-12704` when project schemas mix `VARCHAR2` and `NVARCHAR2`. Format optional source dates according to their inspected physical datatype, and generate target date comparison/parameter expressions by database family rather than reusing Oracle syntax for every ODBC connection.
