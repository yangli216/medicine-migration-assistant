# 药品基础数据迁移写入契约

## 1. 写入边界

一次药品迁移按单行事务写入以下五张表，任一写入失败则整行回滚：

| 顺序 | 目标表 | 作用 | 主键 |
| --- | --- | --- | --- |
| 1 | `hi_bd_med` | 药品通用信息、用药规则、监管属性 | `id_med` |
| 2 | `hi_bd_med_alias` | 药品主别名和检索信息 | `id_med_alias` |
| 3 | `hi_bd_med_unit` | 最小单位、包装单位及其换算系数 | `id_med_unit` |
| 4 | `hi_bd_fac` | 生产厂家；优先复用，不默认创建 | `id_fac` |
| 5 | `hi_bd_med_pro` | 厂家商品、销售包装、进销价和监管编码 | `id_med_pro` |

所有新主键均由 Rust 使用 BSON ObjectId 规则生成，为 24 位小写十六进制字符串。三方提供的目标库引用主键（例如费用归并、厂家主键）也必须是 24 位十六进制字符串，但工具不会替换这些已有主键。

## 2. 字段分层

### 强制字段

- 通用名、物品类型、费用归并、剂型、制剂单位。
- 包装单位、包装系数、生产厂家（厂家主键或厂家名称至少一项）。
- 进货价格、零售价格；允许为 0，不允许负数。

### 条件必填字段

- 非耗材：制剂剂量、剂量单位。
- 非草药且非耗材：默认给药方法、默认频次。
- 机构私有药品：24 位机构主键。

### 可选增强字段

- 一次用量、取整策略、发药方式、皮试、默认滴速。
- 医保等级、基药、处方药、储藏、特殊药品、抗菌药物等监管属性。
- 批准文号、条形码、三方货品码、集采和进口标志。

三方来源中的显示名称必须通过界面值对照转换为新系统字典编码。直接写表不会触发 Java 层的字典转换。

### 药品单位

- 与 PHIS 基础药品维护一致，每个药品无条件确保一条“最小单位 × 1”的 `hi_bd_med_unit` 记录。
- 销售包装与“最小单位 × 1”不同时，再确保一条“销售单位 × 包装系数”记录；相同时不重复写入。
- 商品记录的 `id_med_unit` 仍引用销售包装单位；不存在独立包装时引用最小单位记录。

## 3. 幂等和可见范围

### 基础药品

业务键为“租户 + 通用名 + 物品类型 + 制剂规格 + 可见范围”。中心药品只与中心药品判重；机构私有药品同时检查当前机构私有数据和中心数据，与原 Java 保存逻辑一致。

### 厂家

优先使用已配置的厂家主键；否则按“租户 + 厂家全称”精确匹配。只有批次明确允许时才创建新厂家，避免简称或模糊匹配制造重复数据。

### 商品

优先按“租户 + 三方货品码 + 可见范围”匹配；三方货品码为空时，按“租户 + 厂家 + 商品名 + 销售规格 + 可见范围”匹配。命中后整行标记为幂等跳过，不重复写入。

## 4. 事务、日志和重试

- 每个来源行使用独立事务；五张表全部成功后提交。
- 本地 SQLite 保存来源原文、标准化结果、来源摘要、错误、重试次数和目标主键。
- 新增、复用、跳过、失败分别写审计事件；复用和跳过事件保留匹配业务键作为变更前快照。
- 重试只处理失败行；已成功或已跳过的数据不会重复执行。

## 5. 上线前必须确认的业务边界

原 Java 保存药品后会触发 `medSaveSuccessEvent` 创建或关联基础服务，并回填 `hi_bd_med.id_srv`。直接写表不会触发该事件。当前目标表允许 `id_srv` 为空，数据可以落库，但是否可直接用于医嘱、收费等业务必须由新系统确认。

建议在正式上线前选择并验证一种策略：

1. 允许药品先以空 `id_srv` 迁入，再由新系统提供的正式同步任务补齐；或
2. 提供基础服务表的完整结构、权限和业务规则，将服务创建纳入同一迁移事务。

在规则未明确前，工具只做结构预检并给出警告，不擅自跨 Schema 创建基础服务。
