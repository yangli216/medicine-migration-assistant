# 三方 HIS 来源适配器包

每个适配器使用独立目录和 `manifest.json` 描述能力。应用启动后通过
`list_source_adapters` 读取清单，前端只展示明确支持当前数据库和迁移任务的适配器。

## 两种接入方式

### 通用映射接入

适用于只迁移药品基础信息、项目方能够提供只读 SQL 或 CSV/JSON 的 HIS。

不需要新增 Rust 读取代码。实施人员在应用中配置只读 SQL、唯一来源字段、字段转换和
字典映射，确认后会按“适配器 + 来源实例 + 目标租户”保存为本地模板。

### 自动识别适配器

适用于需要自动识别标准表结构，或需要机构药库/药房库存迁移的 HIS。

1. 使用脚手架创建适配器目录；构建脚本会自动发现目录，不再手工修改 Rust 清单注册表。
2. 在适配包自己的 `adapter.rs` 中仅通过 `super::sdk::*` 实现药品或库存来源契约并返回统一绑定；HIS 专属查询、结构转换和常量都留在包内。构建脚本会自动纳入公共分发，无需修改中央适配器文件。
   Schema、表和视图必须通过 `source_qualified_object` 按数据库家族安全限定；本批机构/库房等文本范围使用 `source_text_filter_list` 生成有上限、稳定排序且安全转义的过滤列表，不在厂商代码中重复拼接规则。
3. 药品识别返回统一的范围、指标、来源对象、警告和预览数据。
   适配器可同时返回 `guidance` 业务说明卡片，公共页面只负责统一展示，不得再按适配器 ID 写死表关系说明。
4. 库存读取返回统一的机构、库房和 `InventorySourceStockItem`；库存分组、金额校验、药品匹配、首次盘点、试迁移和撤销继续复用公共流程。
5. 增加清单解析、数据库兼容、来源表缺失、重复库存和典型项目变体测试。

## 创建与验收

只需要字段映射、无需写 Rust 读取器时：

```bash
npm run adapter:create -- --id VENDOR_HIS --name "厂商 HIS" --database oracle --guided
```

需要自动识别或机构库存时：

```bash
npm run adapter:create -- --id VENDOR_HIS --name "厂商 HIS" --database oracle --tasks MEDICINE_BASE,INVENTORY
```

脚手架会同时生成 `manifest.json`、`acceptance.json`、`adapter.rs.template`、实现清单和 `PROJECT_INTAKE.md`。接入调查清单会把 HIS 版本、稳定键、范围语义、商品关系、字典、库存位置、包装金额和首次盘点边界拆成逐项证据，避免仅凭个人经验遗漏关键口径。将实现模板改名为 `adapter.rs` 后，构建脚本会自动生成后端绑定。把验收文件里的
来源表、稳定键、包装/金额证据与项目变体补齐，并完成后端绑定后执行：

```bash
npm run adapter:status -- --adapter VENDOR_HIS
npm run adapter:verify
```

`adapter:status` 面向开发过程，按包声明、业务契约、来源实现、脱敏夹具和测试证据五个阶段显示当前完成度，只展开最先未完成阶段的代表问题；`adapter:validate` 保留所有严格错误供 CI 和深度排查使用，因此分阶段提示不会降低交付门禁。

`acceptance.evidence` 不是文字标记：每项必须填写所属 `tasks`、`.rs` 文件、真实 `#[test]` 函数名、以该函数名结尾的完整 `rustTest` 路径以及 `REQUIRED` / `OPTIONAL_LIVE` 执行策略。清单声明的每个迁移任务都必须至少有一条证据，药品测试不能替代库存验收。运行 `npm run adapter:evidence` 会逐项精确执行，0 项测试、错误模块路径或把忽略测试冒充必需测试都会失败；`OPTIONAL_LIVE` 仅用于明确使用 `#[ignore]` 的真实数据库验收。`adapter:verify` 已包含这道门禁。

验收会检查清单版本、目录与 ID、数据库和任务能力、重复 ID、连接信息泄漏、自动识别
契约、库存稳定键、包装和金额证据、典型测试场景、可在项目源码中定位的测试证据以及后端实现绑定。任一硬性项不完整时
返回失败，不能把仅能展示名称的半成品适配器当作可交付能力。

每个自动识别适配器还必须在包内提供 `fixtures/*.json`。夹具记录一个真实项目结构变体、
涉及的来源对象与字段、预期通过或阻断结果，以及对应的完整 Rust 测试路径。新夹具使用 v2，
以 `{ name, dataType }` 保留脱敏字段结构，使日期、数值和字符物理类型差异也能回归；旧 v1
字段名数组继续兼容。`adapter:verify` 会拒绝连接信息、样例值和占位内容，再逐个执行对应测试；
桌面开发和正式打包都会经过这道门禁。

构建时会扫描 `src-tauri/adapters/*/manifest.json`（忽略以下划线开头的模板目录），按目录
名稳定排序后嵌入应用。新增或删除适配包都会触发重新生成注册表。

## 教学适配器

`_examples/standard_his` 提供一个不会进入正式运行时注册表的 PostgreSQL 教学适配器。它独立于二系列代码，同时演示药品基础数据和机构库存的完整来源侧路径：

- 仅通过 `super::sdk::*` 调用跨数据库只读查询入口，查询仍会执行 `SELECT/WITH` 限制和 10,000 行上限；
- 从 `information_schema` 生成脱敏表字段快照，并交给公共 `acceptance.json` 契约判断；
- 在可选厂家商品表缺失时改用 `DRUG_ID:BASE` 稳定来源键，不生成无效关联 SQL；
- 使用 `GUIDED` 字段映射和 `GENERIC` 写入语义复用中央药品迁移流程；
- 把 `HIS_ORGANIZATION`、`HIS_STORAGE` 和 `HIS_INVENTORY` 转成公共机构、药库药房、轻量范围和库存明细模型；
- 明细 SQL 只接受本批已选机构与库房，来源标识转义且限制数量，不在范围选择前读取整库药品明细；
- 保留库存行、库房和药品商品稳定键，使用库房实际包装和金额口径；缺少金额合计时按数量乘单价回退，缺少批号效期时不引用不存在的字段；
- 目标机构/库房映射、药品台账核对、目标空库检查、逐库试迁移、首次盘点和安全撤销仍由公共流程负责；
- 配套维护说明、药品/库存结构契约、两类脱敏项目夹具和可执行 Rust 测试。

运行以下命令会验证教学包但不会把它展示给现场用户：

```bash
npm run adapter:examples
```

复制为真实适配器时，将目录移出 `_examples`、改为新的稳定 ID，并替换物理表关系和验收证据。构建脚本会自动发现并绑定，不需要修改中央注册表或前端任务流程。新的自动适配器如果绕过 `super::sdk::*` 直接依赖 crate 内部数据库或编排模块，验收会拒绝。

## 现场识别与排障

- 桌面端只列出同时支持当前迁移任务和数据库类型的自动适配器；没有兼容包时仍可使用通用只读 SQL 完成药品基础数据映射。
- 通用表/视图预览可导出带 SHA-256 的脱敏结构诊断；维护人员运行 `npm run adapter:source-object -- --file <诊断文件>` 校验格式、完整性和隐私边界，并获得字段缺口、数据规模与后续适配建议。禁止根据未经校验或包含原始样例值的文件修改适配器。
- 自动识别结果必须同时给出已核对对象、缺失对象、可迁移范围、指标和提醒，项目表结构不完整时直接显示差异，不能只返回一段数据库错误。
- 药品和库存自动识别都必须把脱敏字段快照交给公共契约判断，并在页面直接显示阻断、需核对和安全降级。库存契约可用 `sourceStructure.objectGroups` 声明“至少存在一个”的来源分支，并用 `requiredWhenObjectsPresent` 只在药库或药房库存表真实存在时激活对应包装、位置依赖，禁止把项目没有使用的库存分支误报为阻断项。
- 诊断历史、当前报告和支持包必须按 `MEDICINE_BASE` / `INVENTORY` 任务隔离。支持包内带有 `migrationTask` 时，`npm run adapter:support -- --file <支持包.json>` 会自动使用对应契约；显式指定其他 `--task` 会直接拒绝。旧支持包不含该字段时仍保持兼容。
- 维护人员可继续运行 `npm run adapter:fixture-draft -- --file <支持包.json>`，从同一份通过完整性和隐私校验的字段快照生成任务级脱敏 v2 夹具草稿。工具只自动填写表字段、数据库物理类型和契约影响，不猜测业务预期或测试路径；`REVIEW`、占位 `rustTest` 或实际没有执行测试的草稿都不能通过交付门禁。
- 现场人员可导出项目差异报告交给适配器维护人员。报告只包含适配器版本、数据库类型、Schema、对象差异、范围和提醒，不得包含主机、端口、账号密码或目标租户。
- 字段映射、转换和来源字典决定按“适配器 + 来源实例 + 目标租户”隔离保存；导出的可移植模板不携带来源实例和目标租户，导入后重新绑定当前项目并校验真实字段。
- 通用来源的唯一标识可由一至三个稳定编号字段按顺序组成，必须在当前整批数据中非空且组合唯一，并由实施人员确认不会复用或变化。模板保存字段数组与顺序，旧单字段模板读取时自动升级；相似来源模板只有在全部组合字段仍存在时才可作为待核对建议。组合值必须使用无碰撞元组编码，不得使用普通分隔符拼接，也不得使用行号、药品名称等临时唯一值代替。Rust 批次准备会再次拒绝缺失、重复或结构化来源键。

## 清单约束

- `packageSchemaVersion`：当前固定为 `1`，不兼容的版本会拒绝加载。
- `id`：稳定、全局唯一的大写标识；发布后不得复用给另一套 HIS。
- `version`：适配器行为版本，读取规则发生变化时递增。
- `databaseFamilies`：只声明经过验证的数据库协议，不做近似兼容猜测。
- `migrationTasks`：当前为 `MEDICINE_BASE` 和/或 `INVENTORY`。
- `automaticDetection`：只有实现标准识别契约后才能设为 `true`。
- `reusableMappingProfiles`：声明字段和字典决策是否可按项目保存。
- `implementation`：后端实现绑定名；通用模式使用 `GUIDED_MAPPING`。
- `medicineWorkflow`：声明药品迁移的公共流程契约。`sourceKeyMode` 决定由实施人员选择一至三个字段，还是由自动适配器提供 `sourceKeyField`；`sourceKeyLabel` 是给实施人员核对的业务名称；`mappingPreset` 选择已注册的字段/字典预设；`batchSourceType` 决定目标写入语义；`factoryPolicy` 决定厂家缺失由公共界面询问还是由适配器关系自动维护；`legacyProfileKind` 仅用于已发布旧模板的兼容读取。新增适配器必须完整声明，公共页面不得通过适配器 ID 或说明文字推断这些行为。
- `inventoryWorkflow`：仅库存适配器声明。`normalizedLocationKinds` 明确适配器会输出标准 `WAREHOUSE`、`PHARMACY` 中的哪些位置，`sourceProductKeyLabel` 给现场人员解释药品商品稳定键。新适配器的 `sourceStockKeyMode` 必须使用 `ADAPTER_SCOPED_V1`，公共层会对适配器、位置类型和来源记录号做无碰撞元组编码；`PHIS27_LEGACY` 只用于二系列既有 `YK/YF` 台账兼容。其余值必须固定为公共安全契约：首次盘点写入、机构映射必需、药品台账必需、每个目标库房试迁移、仅允许校验通过的本批安全撤销；适配器不能通过清单关闭这些门禁。
- `sourceStructure.objectGroups`：声明跨表“至少一个可用”的契约，例如药库库存与药房库存至少存在一种；可结合 `requiredForTasks` 在库存任务中提升为阻断项。
- `requiredWhenObjectsPresent`：仅用于 `CONDITIONAL` 表、字段或字段组；当列出的来源表任一已出现时提升为必需，否则按安全降级处理。适用于“存在药房库存时才要求药房包装表”等分支依赖。

### 库存明细包装证据

`InventorySourceStockItem` 使用厂商无关字段表达包装口径：

- `unitSaleFactor`：当前来源库房/药房实际管理包装系数，与库存数量、单价和金额同口径。
- `singleMinimumPackageFactor`：来源药品主档中可证明“一包装只含一个最小单位”的结构化数值；没有可靠字段时留空，禁止从规格文本猜测。
- `singleMinimumPackageFactorSource`：上述证据的可读物理来源，例如 `DRUG_MASTER.MIN_PACKAGE_FACTOR`；二系列填写 `YK_TYPK.ZXBZ`。
- `productSaleUnit`、`productUnitSaleFactor`：商品主档包装，仅用于与实际库存包装对照，不得覆盖库存位置自己的口径。

公共校验只认标准字段和值，不认识某家 HIS 的表名。适配器负责把厂商字段映射进标准模型，并在业务说明中解释特殊关系。

清单不得包含数据库地址、账号、密码、租户信息或项目专用 SQL。项目专用只读 SQL 和
映射由应用加密连接库及来源模板分别保存。

## 安全边界

- 来源连接始终只读，SQL 仅允许 `SELECT/WITH`。
- 自动库存适配器只负责把来源行转换成公共库存模型，不得自行绕过药品台账、库房映射、空库检查或试迁移门禁。
- 公共边界会校验适配器返回的机构和位置目录、轻量库存范围及正式库存明细：稳定键或名称缺失、位置类型未声明、位置引用未知机构、目录/范围重复、明细越过本批范围或来源记录因关联被放大，都会在目标写入前阻断。
- 当某个库存范围不能唯一定位到实际来源库房时，适配器应返回标准 `requiresSourceLocationResolution=true`，由公共界面要求人工选择。公共层不得通过 `YK:`、`YF:` 等某家 HIS 的私有键前缀推断状态；位置键只需在该适配器来源中稳定、非空且唯一。
- 目标库存仍由公共首次盘点事务写入，时间、ObjectId、审计和安全撤销规则不得在适配器内另写一套。
- 旧适配器升级必须保留来源身份和台账主键语义，避免历史批次无法重试或撤销。
