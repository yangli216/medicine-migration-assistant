# 药品数据迁移助手

一个不依赖 Java 服务端、可直接交付给三方对接人员使用的 Tauri 桌面工具。界面负责引导配置，Rust 负责来源读取、数据转换、直接写表、逐行事务和本地审计。

Windows 桌面首屏只加载认证、任务选择和通用引导所需代码；机构库存工作台与迁移历史在实际打开时按需加载，React 和图标依赖使用独立稳定缓存块，避免复杂迁移功能拖慢启动绘制。

## 当前能力

- 新系统门禁：验证目标系统访问地址，先通过 `/logon/myRoles` 取得并验证 `system` 的 `tenantSystem` 角色，再调用 `/logon/myApps` 完成角色登录；只有返回成功并下发非空 `tk` Cookie 后才允许进入和执行迁移。
- 任务入口：药品基础信息同步、机构库存首次盘点均已开放。选择任务时会直接根据当前适配器清单说明接入路径：药品可选专用自动识别、通用数据库映射或 CSV/JSON；库存只列出真正声明库存能力的专用适配器，明确区分“数据库能连接”和“HIS 业务已适配”。库存任务支持机构/库房映射、逐行核对、金额汇总、空库防重、首次盘点写入和安全撤销。
- 桌面引导：主步骤变化时同步将页面和工作区复位到顶部，不会把上一长页的滚动位置带到新步骤。Oracle、达梦、GBase 等非原生连接默认只展示业务必需参数，本机驱动和高级连接串收进“专家连接选项”；已使用自定义连接串、驱动缺失或未就绪时会自动展开，避免隐藏需处理的配置。
- 来源：CSV、JSON、MySQL、Oracle、达梦 DM8、Gauss/openGauss、海量 Vastbase、南大通用 GBase 8c/8a/8s、人大金仓 KingbaseES、PostgreSQL 只读查询；单批最多读取 10,000 行。没有专用适配器时可直接搜索并选择当前账号可见的表或视图，无需编写 SQL；系统先按严格的药品表名称线索置顶候选，用户可主动对最强的前 5 个候选执行结构快速核对，每个对象最多读取 2 行，再按实际识别到的药品名称、规格、剂型、最小单位、厂家和商品名完整度排序。数量、行数和单候选 8 秒等待上限由桌面 Rust 后端再次强制执行；后端先统一复核对象仍在当前账号可见清单中，失败项只返回受控状态。快速核对不会扫描整个 Schema、不会做行数统计，也不会自动选表；选择候选后仍需完成独立的 6 行正式预览。样例成功后在后台做最多 10,001 行、最长 12 秒的有界探测：小批显示准确行数，大批只提示“至少 10,001 行”并在正式读取前阻止操作，避免为了预检对超大老库执行完整 `COUNT(*)`；探测超时或失败则立即降级，仍允许走正式读取的权威上限校验。驱动不支持字段注释时明确降级为按字段名和样例识别；确认后才重新读取正式批次。遇到无法判断的项目结构时，可直接导出脱敏结构诊断 JSON，交付字段名、注释、来源、样例非空率、长度/类型形态、行数探测和药品字段线索；诊断文件不包含数据库地址、端口、账号密码、高级连接串、目标租户或任何原始样例值。线索不代替正式字段映射和业务校验，切换连接或对象会使旧样例和旧探测立即失效。多表关联查询保留在高级方式中。
- 大型 Schema 的表/视图选择会把名称含 DRUG、MEDICINE、YK_TYPK、YK_YPCD 等明确药品线索的对象优先分组，目录/主数据名称靠前，流水、价格、库存明细名称降级提示；这只是名称导航，不会自动选择或代替样例核对。搜索始终覆盖完整可见清单，不受首屏 150 项展示上限影响。
- 二系列phis适配：以 `YK_TYPK`、`YK_YPCD` 为药品主表，厂家读取 `YK_CDDZ`；提供“机构在用药品”“机构全部配置药品”“全部通用药品”三个范围。“机构在用”仅以有效 `YK_CDXX` 判断，库存读取 `YK_KCMX` / `YF_KCMX`。标准药品、机构和库存查询会先读取实际字段，核心关联字段缺失时给出明确清单，批号、效期、来源金额合计及描述字段缺失时使用空值或安全计算值继续核对。
- 映射：推荐映射、逐字段确认、完整映射专家模式；支持可视化“旧值 → 新值”字典、默认值、大小写、空白清洗、整数/小数、布尔和日期标准化。
- 在线字典：依据 `HiBdMed` 的 `@Dictionary(id=...)` 白名单，在 system 登录后复用 `tk` Cookie，以最多 6 路并发读取当前租户真实字典；界面展示编码与名称，可按编码、名称、拼音及常见组合格式生成安全映射，预校验会拒绝已加载字典范围外的编码。
- 费用归并：登录后调用 `api/base.tenantDicService/medicineCostMerge` 读取当前租户归并项目；按药品类型推荐“西药→西药费、草药→草药费、疫苗→疫苗费、耗材→卫生材料费、中药/民族药/院内制剂→成药费”，由对接人员逐项确认后写入 `hi_bd_med.id_cstmg`。
- 校验：必填、长度、枚举、数字、条件必填和业务冲突检查。
- 写入：MySQL 和 PostgreSQL 兼容家族使用应用内置原生协议，其他企业数据库使用已安装的厂商 ODBC，直接写入 `hi_bd_med`、`hi_bd_med_alias`、`hi_bd_med_unit`、`hi_bd_fac`、`hi_bd_med_pro`。每条来源记录独立提交或整体回滚。
- 分层写入：没有厂家商品数据时仅写药品、单位和基础别名；存在厂家商品数据时才继续校验并写入厂家与商品表。
- 可靠性：每条来源记录使用独立数据库事务，单条失败不影响其它记录；可仅重试失败记录。
- 增量：本机 SQLite 维护“租户 + 来源 + 来源主键 → 目标主键与来源摘要”的迁移台账；来源未变化时自动跳过，检测到已迁移来源发生变化时阻止静默覆盖并提示进入覆盖流程。
- 来源主键：通用文件或数据库读取完成后，会使用整批数据检查非空、唯一、标量类型和稳定键命名线索；单字段不能唯一时，可按顺序选择最多三个稳定编号字段组成业务键。系统只自动推荐带主键/编号线索且整批组合后唯一的结果，药品名称等可变属性即使暂时唯一也不会静默推荐。组合值使用 JSON 元组编码，原值包含冒号、竖线等分隔符时也不会碰撞；实施人员仍须确认所选字段不会复用或变化。字段数组及顺序会随来源模板保存，旧单字段模板自动兼容；前端准备和 Rust 批次后端都会拒绝空键、重复键、数组/对象键，永不使用行号兜底。
- 幂等：药品和产品按业务唯一条件复用或跳过，避免重复执行产生重复数据。
- 审计：批次、行状态、目标主键、写入清单、前后数据摘要、错误和操作时间写入本机 SQLite。
- 安全撤销：覆盖记录先按字段级快照恢复，再删除审计中明确标记为本批次 `INSERT`、属于当前登录租户、且未被后续数据引用的记录；复用数据永不删除。撤销前必须核对执行时记录的目标库身份，存在后续引用时保留记录并标记为部分撤销；来源台账也同步恢复到覆盖前版本。
- 覆盖迁移：仅允许覆盖迁移台账确认由本工具创建或连续覆盖的药品、商品记录；正式执行前必须从目标库生成逐行字段差异，支持勾选部分记录，未勾选记录进入可审计的跳过状态。更新前保存实际数据库字段原值，更新与快照读取位于同一事务。厂家、包装单位采用匹配或新建，不直接覆盖共享主数据；暂不允许在“仅基础药品”和“含厂家商品”之间改变数据层级。
- 安全：新系统密码在 Rust 后端按 MD5 接口协议转换，`tk` 仅保存在内存 Cookie 会话。选择“记住密码”时，数据库和新系统口令使用应用数据目录中的每安装实例主密钥进行 AES-256-GCM 本地加密，不依赖 macOS 钥匙串，也不写入审计记录。药品基础数据固定为租户级公共数据，`id_tet` 和操作人由后端登录会话强制赋值。MD5 不是传输加密，正式环境仍建议使用 HTTPS。
- 主键：所有新建记录使用 BSON ObjectId，固定为 24 位小写十六进制字符串。

## 使用方式

开发预览：

```bash
npm install
npm run desktop:dev
```

生成当前操作系统的免服务端桌面安装包：

```bash
npm run desktop:build
```

### Windows EXE

仓库提供 `.github/workflows/windows-build.yml`。进入 GitHub 仓库的 **Actions → Build Windows installer → Run workflow**，构建完成后下载 `medicine-migration-assistant-windows-x64`，其中包含可直接安装的 NSIS `.exe`。

Windows x64 是驱动准备和安装包验收的第一优先级，macOS Apple Silicon、macOS Intel 依次验证。MySQL 原生协议和 PostgreSQL 通用协议随应用内置；PostgreSQL、openGauss/GaussDB、Vastbase、GBase 8c、KingbaseES 默认无需安装 ODBC。Windows x64 安装包同时内置 Oracle Instant Client 19.31 完整 Basic + ODBC，安装时自动登记应用专用驱动，因此会申请管理员权限；达梦、GBase 8a/8s 等厂商 ODBC 仍由项目安装介质或厂商提供。

Windows 流水线从 Oracle 官方地址下载固定版本驱动并核对 SHA-256，不把大体积厂商文件提交到 Git。它不仅生成 NSIS 安装包，还会在干净的 Windows x64 Runner 中执行静默安装，核对程序为 x86-64 PE、Oracle 许可及运行文件齐全、64 位 ODBC 登记指向应用目录，并实际启动桌面应用，最后输出 `windows-install-acceptance.json`。本地 Windows 也可运行：

```powershell
npm run verify:windows
```

### macOS 签名与公证

`.github/workflows/macos-release.yml` 只接受正式 Apple Developer 凭据，构建后强制执行代码签名校验、Gatekeeper 评估和公证票据校验。仓库需配置以下 Secrets：

- `APPLE_CERTIFICATE`：Developer ID Application 的 Base64 `.p12`
- `APPLE_CERTIFICATE_PASSWORD`
- `APPLE_SIGNING_IDENTITY`
- `APPLE_ID`
- `APPLE_PASSWORD`：Apple 专用密码
- `APPLE_TEAM_ID`

缺少任一项时流水线会明确失败，不会把自签名或未公证产物作为发布包。开发机可使用自签名证书检查包结构和代码签名，但只有 Developer ID + Apple 公证结果才算正式验收：

```bash
npm run verify:macos
REQUIRE_NOTARIZATION=1 npm run verify:macos
```

## 三方 HIS 适配器维护

三方 HIS 适配器位于 `src-tauri/adapters/<adapter>/`。每个适配器包独立声明支持的数据库、迁移任务、实现绑定、模板兼容起始版本和当前版本变更说明；新增包请通过脚手架创建，避免在主界面或中央分发器中追加厂商专用分支。

```bash
npm run adapter:create -- --id VENDOR_HIS --name "厂商 HIS" --database oracle --guided
npm run adapter:status -- --adapter VENDOR_HIS
npm run adapter:verify
```

自动识别或库存适配器的脚手架会生成 `PROJECT_INTAKE.md`，把 HIS 版本边界、稳定来源键、迁移范围、药品商品关系、字典语义、机构库房、选择后过滤、包装金额和首次盘点边界整理成逐项调查证据；库存验收契约和 v2 夹具也会预置机构、库房、库存行、药品商品键、数量价格及管理包装字段，维护人员不需要从空白文件开始设计。

开发过程中使用 `adapter:status` 查看就绪诊断：它按“适配包声明、来源结构与业务口径、来源读取与公共 SDK、脱敏夹具、可执行证据”分阶段展示完成度，只展开当前阶段的代表问题和下一步。需要 CI 级完整错误时再运行 `adapter:validate`，最终交付仍必须通过 `adapter:verify`。

`acceptance.evidence` 的每条业务证据必须同时声明所属迁移任务、Rust 源文件、测试函数名、完整 `rustTest` 路径和执行策略。每个适配器声明的 `MEDICINE_BASE` / `INVENTORY` 任务都必须有证据覆盖，不能用药品测试替代库存验收。`adapter:evidence` 会精确执行每个必需测试并拒绝“命令成功但实际运行 0 项”；依赖真实数据库的测试只能显式标为 `OPTIONAL_LIVE`，且源码必须使用 `#[ignore]`。该门禁已包含在 `adapter:verify` 中。

自动识别或库存适配器还必须提供验收清单、脱敏项目差异夹具和可执行 Rust 回归测试。`adapter:verify` 会同时检查清单、实现绑定、凭据泄露、版本兼容范围、当前版本变更说明和夹具是否真实执行，未完成的适配器不会进入交付构建。

库存适配器不需要手工填写整张公共结构体。SDK 构造器把维护工作拆成稳定身份、药品信息、库房包装、商品对照和库存金额几组；`new` 强制给出机构、位置、来源记录和来源商品键，其余字段只在老系统确有可靠依据时补充。目录和预检结果也不再要求厂商代码重复填写适配器名称、版本与汇总数量：公共层会从清单和位置明细自动补齐，并拒绝摘要与明细不一致的实现。脚手架生成的 `adapter.rs.template` 已包含同样的映射示例，公共边界仍会统一检查范围越界、关联放大、重复键和包装证据。

来源 SQL 的动态部分也由公共 SDK 收口：`source_qualified_object` 按数据库家族处理 Schema、表和视图引用，`source_text_filter_list` 为本批机构/库房生成最多 500 项、稳定排序且安全转义的文本过滤列表。教学适配器实际使用这两项能力，新厂商无需复制引号和转义实现。

```rust
InventorySourceStockItem::new(kind, record_id, location_key, location_name, organization_id, product_key)
    .with_medicine(name, specification, dosage_form, minimum_unit)
    .with_storage_packaging(sale_unit, sale_specification, unit_sale_factor)
    .with_single_minimum_package_evidence(factor, "DRUG_MASTER.MIN_PACKAGE_FACTOR")
    .with_product(factory_name, product_name)
    .with_quantity_and_prices(amount, price_pur, price_sale)
    .with_totals(purchase_total, retail_total)
    .with_batch(batch, expiry)
```

现场识别三方库后，应用会按来源指纹在本机保留最多 20 次结构变化，并在药品与库存任务中直接显示“阻断项、需核对、可兼容降级”摘要；阻断项会停止标准读取，现场人员无需先导出文件才能知道项目差异是否影响迁移。库存判断支持“药库或药房库存至少存在一种”的跨表契约，并只在对应库存分支实际存在时要求该分支的包装和位置字段，避免无药房项目被药房字段误阻断。可以单独导出包含该契约影响的当前差异报告，也可以导出带校验值的 JSON 支持包交给维护人员；v2 支持包会记录已核对表的字段名称和数据库类型，并直接比较新增字段、缺失字段及类型变化，但不会记录字段注释、SQL、数据库地址、端口、账号密码、原始来源身份、目标租户、样例值或任何业务数据。维护工具继续兼容不含字段结构的 v1 支持包。通用数据库模板按“来源实例 + 具体表/视图或只读查询指纹 + 目标租户”隔离，同库切换对象不会套用另一张表的映射；旧版数据库级模板只有在保存查询与当前来源完全相同时才会兼容恢复，并会立即复制为当前对象级模板，恢复后可直接导出和在下次读取时复用。自动复制失败不会中断本次数据读取，但会明确提示重新保存并暂时禁用导出。仅使用 ODBC 高级连接串时，会先剔除账号密码再对非敏感连接属性生成本地指纹，不会因密码变化丢失模板，也不会在模板键中保留连接串原文。模板升级只在适配器声明的兼容版本范围内自动复用，超出范围会要求重新核对，来自未来版本的模板会被拒绝。

诊断历史、当前报告和支持包按药品基础与机构库存任务分开保存，两类结构识别不会相互覆盖。新导出的支持包带有任务标记，离线维护工具会自动套用对应契约；药品支持包不会被当作库存问题分析，反之亦然。旧版未带任务标记的支持包仍可继续分析。

如果当前来源没有精确模板，应用会在同一目标租户的本机历史中查找同适配器、已映射字段结构完全可用的最近模板，并将它作为“需核对”的字段建议。该建议只复用字段映射和受限转换规则，不会执行旧 SQL，也不会复制连接身份或来源字典；旧唯一标识在当前字段中不存在时会被清空。确认后的配置才会保存为当前来源自己的独立模板。

维护人员收到支持包后可直接生成结构变化摘要；命令会先核对 SHA-256、格式、历史上限和敏感字段，再列出当前缺失对象、已恢复对象、新增可见对象与指标变化。专用适配器的 `acceptance.json` 使用 v2 机器可读 `sourceStructure` 契约声明每张表和字段是必需、条件依赖还是可选，同时记录受影响业务、允许的数据类型和安全降级方式；分析结果会直接分成“阻断项、需核对、可兼容降级”，维护者不必仅凭字段名猜测影响：

```bash
npm run adapter:support -- --file ./现场支持包.json
```

带任务标记的新支持包会自动选择 `MEDICINE_BASE` 或 `INVENTORY` 契约；如果显式传入与支持包不同的 `--task`，分析器会拒绝处理。旧支持包不带任务标记时，可增加 `--task MEDICINE_BASE` 或 `--task INVENTORY`；未指定任务时仍会检查完整适配器契约，适合版本发布前的全量审计。

需要维护 `acceptance.json` 时，先生成独立的差异草稿。工具只从通过完整性和隐私校验的 v2 支持包提取表名、字段名与类型族，自动列出新增候选和现有契约阻断项；草稿不会直接覆盖验收契约，也不会包含来源指纹、Schema、样例值、SQL、字段注释、连接信息或租户信息：

```bash
npm run adapter:contract-draft -- --file ./现场支持包.json --output ./contract-draft.json
```

带任务标记的支持包可省略 `--task`；旧支持包必须明确指定一个任务。维护人员应删除无关候选，并补齐业务用途、必要性和安全降级方式，再手工合入 `acceptance.json`、脱敏夹具及对应可执行回归测试。含 `TODO` 的草稿不是可交付契约。

同一份已校验支持包还可生成项目变体夹具草稿，自动带出任务、数据库家族、当前表字段及物理类型和契约阻断/核对/兼容降级项。v2 夹具以“字段名 + 数据库物理类型”保存脱敏结构，能够回归 DATE/字符日期、NUMBER 精度、VARCHAR2/NVARCHAR2 等会改变 SQL 生成的项目差异；验收继续兼容仅含字段名的 v1 夹具。输出不含来源指纹、Schema、样例值、SQL、连接或租户信息：

```bash
npm run adapter:fixture-draft -- --file ./现场支持包.json --output ./project-variant.draft.json
```

契约明确阻断时草稿建议 `BLOCK`，完全兼容时建议 `PASS`，仍需业务核对时使用不可交付的 `REVIEW`。维护人员必须改写可读标题和业务检查项、将 `REVIEW` 明确决定为 `PASS` 或 `BLOCK`，并填写真实可执行的 `rustTest` 路径后，才能把文件移入适配器的 `fixtures` 目录。验收会拒绝占位测试路径，且夹具测试实际执行为零项时仍视为失败。

没有专用适配器时，现场人员可在通用表/视图预览区导出“脱敏结构诊断”。维护人员使用以下命令离线核对 SHA-256、格式、字段数量、药品线索、样例形态和隐私边界；文件被修改、出现未知字段、连接凭据、租户或原始样例值时会直接失败。通过后会列出缺失药品字段、注释覆盖率、数据规模和下一步建议：

```bash
npm run adapter:source-object -- --file ./generic-source-object-diagnostic.json
```

每个适配器包都必须包含 `MAINTENANCE.md`，记录版本兼容、现场差异处理和交付门禁。脚手架会自动生成该文件，验收命令会拒绝缺失或仍有占位内容的维护说明。

仓库还包含一个不会进入正式运行时清单的 `STANDARD_HIS` 教学适配器，用 PostgreSQL 示例表验证第二家 HIS 可以只通过公共 SDK 完成药品及机构库存结构识别、受限只读查询、稳定来源键、机构库房目录、轻量库存范围、本批明细和通用字段映射，而不修改中央注册表、前端任务流程或目标写入逻辑。库存示例只负责来源标准化，继续复用公共机构/库房映射、药品台账、空库检查、试迁移、首次盘点和安全撤销。`npm run adapter:verify` 会额外执行 `adapter:examples`，同时确认教学包可编译、药品/库存夹具可执行，并且正式适配器注册表仍只包含可交付能力。

## 数据库支持范围

MySQL 使用应用内置原生协议。PostgreSQL 兼容家族优先使用应用内置的 PostgreSQL 前端协议：PostgreSQL、openGauss/GaussDB、海量 Vastbase G100、南大通用 GBase 8c 和人大金仓 KingbaseES；连接测试、只读查询、表清单、目标结构检查、药品基础数据增量写入和安全撤销均不依赖本机 ODBC。每条药品来源记录在同一事务中完成药品、别名、包装单位、厂家和厂家商品写入，任一步失败整行回滚。特殊版本可在连接表单的高级区域显式配置厂商 ODBC 回退。

Oracle、达梦 DM8、南大通用 GBase 8a/8s 默认使用 64 位 ODBC。其中 Windows x64 的 Oracle 19.31 驱动已内置并自动登记；保存的 `Oracle 19 ODBC driver` 配置会自动解析为应用专用驱动，不覆盖电脑原有 Oracle 客户端。该内置客户端支持 Oracle Database 11.2.0.4 及以上；更早的 11g 小版本需要升级数据库补丁，或在 Windows 安装匹配的 64 位 Oracle ODBC 驱动并在连接中明确选择。`ORA-01017` 表示已经到达数据库服务但账号认证失败，应核对密码大小写、Service Name 和账号密码验证器，而不是重新安装驱动。GBase 产品必须选择具体分支，不能把 8a/8s 当作 8c 的 PostgreSQL 协议连接。PG 通用协议已覆盖药品基础数据增量写入与安全撤销，以及机构库存的库房读取、首次盘点和安全撤销；覆盖写入仍需显式使用已验收的厂商 ODBC。首次盘点在正式写入前会验证所有业务字段，ODBC 回退按数据库家族选择日期表达式，不再统一套用 Oracle 语法。

## 驱动预置策略

驱动中心清单位于 `src-tauri/driver-packs/manifest.json`，编译时会嵌入桌面程序。它统一提供默认端口、协议、推荐驱动名、版本、识别关键词、交付方式、官方地址、逐步安装指引和平台优先级。

| 数据库 | 预置方案 | 二进制交付 |
| --- | --- | --- |
| MySQL | 原生 Rust 驱动 | 已内置 |
| PostgreSQL | 通用 PG 前端协议 | 已内置 |
| Gauss/openGauss | 通用 PG 前端协议优先 | 已内置；特殊版本可显式回退厂商 ODBC |
| 海量 Vastbase G100 | 通用 PG 前端协议优先 | 已内置；项目专用驱动从安装介质或海量支持获取 |
| 南大通用 GBase 8c | 通用 PG 前端协议优先 | 已内置；厂商包从 GBase 8c 下载中心获取 |
| 人大金仓 KingbaseES | 通用 PG 前端协议优先 | 已内置；特殊兼容版本可回退厂商 ODBC |
| Oracle | Instant Client ODBC 19.31 64 位 | Windows x64 安装包内置完整 Basic + ODBC；自动登记和卸载应用专用驱动，保留 Oracle 许可文件 |
| 达梦 DM8 | 厂商 ODBC | 从达梦官方客户端或项目授权安装介质获取 |
| 南大通用 GBase 8a | 厂商 ODBC | 从官方下载中心查找；Windows 驱动缺失时按官方说明向技术支持申请 |
| 南大通用 GBase 8s | 厂商 ODBC | 从官方下载中心或项目安装介质获取 |

厂商驱动二进制必须与应用位数、操作系统和 CPU 架构一致，Windows 统一按 64 位准备。Oracle 包在构建时从官方地址取得、按固定 SHA-256 校验并保持原文件不变；其他未允许重新分发的厂商驱动只内置配置、检测规则和下载说明，不把授权二进制打入公共安装包。

## 代码结构

- `src/App.jsx`：迁移流程状态和命令编排，不再承载所有界面实现。
- `src/PrimaryFlowScreens.jsx`：登录、任务选择、数据来源和来源识别。
- `src/DatabaseConnections.jsx`：可复用数据库连接管理。
- `src/InventoryMigrationScreen.jsx` / `src/InventoryReview.jsx`：库存映射、核对、执行和撤销界面。
- `src/MigrationHistory.jsx` / `src/MigrationResults.jsx`：历史审计与校验结果。
- `src-tauri/src/inventory.rs`：库存模块入口；预检、撤销、正式写入和映射逻辑分别位于 `src-tauri/src/inventory/`。
